## Scenario Learning System 问题分析

### 1. 情境练习表与课程词汇包表的关系

**你的理解是正确的**。从表结构看：

- `sl_exercises.vocab_package_db_id` 关联到 `generated_vocab_packages.vocab_package_db_id`
- 一道题确实对应课程词汇包表中的一个记录

### 2. 课程词汇包表的设计问题

**这里存在设计问题**。根据文档：

- `generated_vocab_packages` 表只有 `lesson_db_id` 和 `vocab_uuid` 两个外键
- 这意味着一个 `lesson_db_id` 可以对应多个 `vocab_uuid`（一对多关系）
- 但每个 `vocab_package_db_id` 确实只对应一个词汇

### 3. 词汇库表的元数据存储问题

**文档中存在逻辑缺陷**。`vocabulary` 表结构中只显示了：

- `vocab_uuid`, `word`, `hsk_level`
- 但文档提到"允许同一个词在不同难度等级下有不同的元数据"
- **问题**：表结构中没有显示存储"元数据"的字段

## Content System 问题分析

### 1. 课程_单词关联表的关系

**不是一对一关系**。从表结构看：

- `lesson_words` 是多对多关联表
- 一个 `lesson_id` 可以关联多个 `word_id`
- `display_order` 字段表明一个课程中有多个单词的学习顺序

### 2. 题目表的内容存储设计

**是分开存储的**，这是合理的设计：

- `prompt`（TEXT）：存储题目的文本描述
- `metadata`（JSONB）：存储结构化的交互数据（选项、答案等）
- 这种分离符合"内容与数据分离"的设计原则

### 3. 父题子题的设计

**采用自引用外键设计**：

- `parent_exercise_id` 字段引用同表的 `id`
- `NULL` 表示父题（顶级题目）
- 非 `NULL` 表示子题，值为父题的 `id`
- 支持无限层级嵌套（试卷→大题→小题）
